## 2. What shipped today

Twenty-five commits. The first eight are the workflow's; the rest came from an
assessment of the generated chain on **Laila New 2** and the work it ranked.

**The premise this session established** (operator direction, recorded in
`aura-provisional-premium-premise` memory): a provisional chain — ontology and
everything downstream, before any interview — must still produce a fully
functional prototype that is accurate per industry standards and looks premium.
Uncertainty belongs in grounds, tooltips and the question pack, **never in the
pixels**. The Laila CRM app (`~/laila-crm`, demo mode on :8080) is the bar.

### The chain now carries facts, not recall

- **Standard packs state attributes and cardinality priors** (`ProvisionalPackAttribute`,
  `ONTOLOGY_VERB_PRIORS` + explicit per-association overrides). The reconciler
  writes both onto entities and relations **regardless of what the drafts
  recalled** — drafts' own priors are discarded by the vote, which is why this
  had to be code and not prompt.
- **A name collision is not a fact collision.** Drafts copy the backbone's
  attribute NAMES and none of its facts — measured live: 72 attributes, zero
  with a `kind`, value set or bound. The merge now enriches a drafted attribute
  instead of skipping it. After the fix, live: **68 of 68 attributes carry
  `kind`**, 16 carry value sets, `intentScore` carries `min: 0, max: 100`, and
  **11 of 11 relations carry a standards prior**.
- **Seed coherence.** A record is one thing that happened: bounded numbers draw
  inside their bounds; no date precedes the record's own start (renewal/review
  dates used to, on 3 of 8 contracts); a secondary state cannot disagree with
  the primary about whether the story is over (stage "Closed Won" + forecast
  "Pipeline", on 3 of 8 opportunities). Repairs spend no randomness — two runs
  over one ontology still seed byte-identical rows.

### The build renders the design

- **ED verbs are wired or refused.** `primaryActions` resolve against the
  ontology into `set` / `create` / `assign`, or are refused by name into gaps.
  A control that cannot act is not drawn. Live: 4 wired across Lead and Order.
- **Wireframes direct the build** — table/list blocks choose columns and
  collections; metric blocks become stat widgets through the same validation a
  model-authored screen spec gets; `states.empty` supplies empty-state copy.
- **Journeys are repaired, not just missed.** Each Atlas workflow with no
  journey is transcribed into one (its name, owner, steps, systems, agent),
  stamped `derived` with its basis. Live: 1 journey → 6.
- **Chip toning.** `valueTone` gives a verdict-carrying state its colour;
  health/priority used to be pinned to `--warn` for EVERY value, so "Healthy"
  rendered as a warning. Bare magnitudes ("High") are deliberately untoned.
- **Blueprint invariants enforced**: an `act` agent on irreversible/high-blast
  work with no gate is demoted to `act-with-approval`; coverage and completeness
  breaches become named gaps.
- **Presentation integrity**: a stylesheet that cannot parse is rejected
  (`checkStylesheetSyntax`), a broken prior skin is never re-adopted, and
  stylesheet mode now asks for `styleTokens` — slot-checked token values, sheet
  rebuilt deterministically — instead of model-authored CSS.
- **Honesty**: seeds read as a book of business (no Northwind/Contoso, no
  self-described stress fixture), methodology vocabulary is gone from every
  stakeholder surface, the chrome carries the programme's name, and a build's
  confidence is capped by its weakest input with the cap stated.

### Process changes

- **`check:edge-syntax` is in `validate`** — esbuild over `run-agent` + every
  `_shared` module. The deploy-only failure class (§4.1 of the old handover) now
  dies locally in ~20ms.
- **Regeneration applies directly** (operator direction). The propose-then-confirm
  inbox step is gone; a regeneration that replaces hand edits or covers less than
  the record says so in the artifact's own gaps and leaves an attestation.
- **Design Loop tile order** is shape ▸ experience / agents ▸ build — generation
  order, so tiles light up left to right.

## 4. Traps this session actually hit — all of them cost real time

1. **Backtick inside a template literal.** Hit TWICE more today (a comment in
   the client renderer, a comment in the stylesheet) on top of the three the
   morning recorded. Both were caught in seconds because the class is now gated:
   `npm run check:edge-syntax`, and `validate` runs it second.
2. **A drawn control whose handler was never exported.** `doAct` was defined
   inside the renderer and not attached to `window`, so every designed verb was
   a button that did nothing — the exact defect the module forbids. Every
   structural test passed it; the **click-through** test caught it. Optional
   renderer segments must export their own handlers (`window.decide` is the
   precedent).
3. **`Object.entries` over a `Map` returns nothing, silently.** The tone lookup
   was built from `tables` (a Map) and shipped empty; the test caught it, the
   code would not have.
4. **A repair that reached for the wrong vocabulary.** The state-agreement rule
   fell back to the generic `STATUSES` pool, which wrote a status word into a
   category column. An existing 33-entity measurement caught it. A secondary
   may only move within its OWN stated vocabulary.
5. **A guard that fires on correct output is worse than no guard.** Six of
   twenty-four verb refusals were capabilities the build already had ("Create
   Campaign" IS the New button); a persona-coverage check I wrote fired on a
   clean blueprint. Both were removed. A gap channel that cries wolf stops
   being read.
6. **Do not attribute a platform failure to your own change.** The ontology vote
   began returning `WORKER_RESOURCE_LIMIT` and I blamed the context growth I had
   just shipped. The run rows disproved it: `tokens_used` was **null** on every
   failure (no model call ever completed) and the deployed code was identical
   across the last success and the first failure. It cleared on its own ~40
   minutes later, completing in 22s. The speculative batching change made in the
   meantime was **reverted** rather than left in.
7. **Regenerations coalesce.** A run with `triggeredBy` other than `"user"` is
   skipped if an identical agent+program+phase ran within 5 minutes — repeated
   Regenerate clicks appear to do nothing. The app's own operator path sends
   `"user"`.
8. **G3 guard**: no client name in any `_shared` source, including comments.
9. If you touch `prototypeDesignSystem.ts`, regenerate
   `public/prototype-design-system.html`:
   `npx esbuild supabase/functions/_shared/prototypeDesignSystem.ts --format=esm > .tmp-ds.mjs && node scripts/build-ds-demo.mjs` (then delete `.tmp-ds.mjs`).
   Never hand-edit it.
10. **Claims register**: rewording a claim line in a prompt or UI surface trips
    `claimsRegister.test.ts`. Re-status the row in `docs/aura/claims-register.md`,
    then `npm run claims:regen`. Rows 19 and 20 were added today.

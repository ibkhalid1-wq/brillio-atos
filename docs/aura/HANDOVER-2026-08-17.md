## 2. What shipped, and the reasoning that will not be obvious from the diff

Twelve commits. Grouped by the problem each solved.

### A decision that must survive regeneration has to be DATA, not pixels

Three symptoms of one problem: stakeholders answered questions and the answers
closed nothing; operators renamed things and the next build erased them; and
pointing at a screen — the one gesture that carries an address — was unused.

- **`designOverrides.ts`** is the prototype's equivalent of `flowOperatorOverrides`,
  which has existed for the evidence documents since the beginning precisely
  because "the doc is REPLACED on regeneration". Overrides are addressed by the
  **source tuple** the fabric node carries (`{entity, attribute}`), never by the
  fabric id — the id is derived from names and dies of a rename it has nothing
  to do with. A tuple that no longer resolves becomes a NAMED orphan in the
  build's own gaps, with a single suggested re-bind when the world holds exactly
  one candidate. **Nothing is re-bound automatically**; that would move
  somebody's decision onto a field they never saw.
- Stored at `phaseInputs.envision._designOverrides` — the same underscore-prefixed
  overlay channel the gap routes and role bindings use, so it stays out of the
  movement fingerprint.
- **The answer ingest** (`stakeholderAnswers.ts`) is built as a READER over
  evidence already on the record, not a second write path. The discriminator is
  the `[locus: …]` tag itself: only the response surface behind somebody's own
  token-gated link produces one, so an operator's retyping still closes nothing.
  That boundary is now enforced by the shape of the evidence rather than by
  convention.
- **Annotate** (`prototypeAnnotate.ts`) injects a click-catcher into the
  PREVIEW and never into the stored bytes. A persona queue is not a fabric node
  and the front door is made entirely of them, so the assembler writes
  `data-entity` onto each queue slot — otherwise the most-visited screen was the
  one nobody could annotate.

### The prototype is the one artifact you can judge by looking at it

- The Design Loop draws the build on its own stage (`PrototypeStage`) instead of
  a fourth identical tile. It renders at 1,280 and scales to fit; `sandbox="allow-scripts"`
  because the build draws its records through its own renderer, and withholding
  scripts staged an application with every table empty.
- The studio previews `prototypeBaselineOfProgram` — the edge's own baseline
  builder — so operator preview, stakeholder link and the refine post-condition
  are the same build by construction rather than by a matching argument list.

### The walk reaches the bottom

Child collections rendered their rows with the row-action flag off, so from an
Account you could SEE its Opportunities and not reach one. Every entity
reachable from the menu HAS a detail screen — that is what the closure is for;
only the LIST is optional, which is why "View all" is gated on `listed` and the
row's own way in is not. The drill-down then moved INTO the record's name
(operator direction) and the Actions column went entirely.

### Composition and craft

Six changes, assessed against the design system's own reference page. Numeric
columns right-aligned head and body; the detail screen composed as two columns
above 1,040px; the definition list laid out as rows; the type step added; each
platform's UI face named explicitly (the document is self-contained and cannot
fetch a webfont, so the fallback had to become a choice).

**And the one that mattered most, which no test caught:** all of it landed, the
suite went green, and the live preview was byte-identical. A prior build's
stylesheet is re-adopted as "the skin the operator approved" whenever it differs
from stock — and that test cannot tell a deliberate restyle from a sheet that is
merely OLD. So the day the design system improves is the day no existing
programme can receive it. Hence `--m-ds`: a skin from an earlier system is
refused rather than held onto, and a hand-authored one is stamped on the way in
so it is not dropped on the next round.

### A workbench is a place, not a person

Grouping by the workflow's owner made a menu of job titles — "Sales reps -
Markets", "Sales Leaders - Markets", "GTM Leaders - Practices", "Executive
Sponsor". The atlas has carried `area` all along. **Measured, and the count does
NOT drop** (11 owners, 11 areas on the snapshot); what changes is what the names
are. The header says WHERE and the step says WHO, so nothing is lost.

Then the band above the queues: **"Waiting on you"**, listing what is off track
or awaiting a gated agent's approval, in the order somebody would work it, and
saying plainly when there is nothing. Nothing new is computed — the tone table
already knows which status words carry a verdict (so "Cancelled" surfaces and
"Prospecting" does not), the blueprint already says which agents cannot act
alone, the queues already carry each entity's status column.

### One build, not two

The Live / As generated toggle is gone; **Live stays**. As generated was a
snapshot whose only unique content was the refine's in-region work — which does
not survive the next generation anyway, since only the stylesheet carries. It
preserved something already doomed while making it look durable, and offered a
stale build to show in a review. "Edit this build" went with it: it edited the
STORED document, so its edits were bytes, and bytes are what a rebuild erases.
Annotate is the editing path; the source editor stays reachable from Import.

### The Discovery Kit could not be scrolled

Two traps stacked, and a third underneath. The overlay's only scroller was the
document BODY, with the ask panel and the coverage matrix pinned above it as
siblings — on a real kit the matrix is 756px in a 773px column, so the document
was squeezed to 62px. The embedded variant of the same studio has scrolled as
one panel since it was written; the overlay never got that treatment. Then the
matrix was scrollable **by one pixel** (493px of content in a 494px cap), which
is enough for the browser to treat it as the scroller under the pointer and
never chain the wheel — so with the cursor over the grid it still felt frozen.
And the outline's scroll-spy was rooted on `.v3fs-docview-b` BY NAME, an element
that is not the scroller in either variant; it now finds the nearest ancestor
that actually scrolls, by measurement.

### The most direct evidence a programme gets could not reach the ledger

A stakeholder talking in a meeting is the strongest testimony there is, and it
was the one kind with no route in: a question pack carries its loci out and
home, while a transcript is prose with no addresses in it.

`reviewCapture.ts` is the route, and the whole design turns on one refusal — a
model deciding which question a sentence answers is doing something useful that
is **not testimony**. So it MATCHES and a person CONFIRMS. The reader throws
away a locus this review never asked about (an invented address would close a
question nobody put), a quote too short to confirm, and any closure attributed
to the machine or to nobody; each throw is reported, never silent. Two people
disagreeing both survive — adjudication is not the model's. The confirmed row
goes through `_stakeholderAnswers`, the writer that already existed, with
`method: "transcript"` and the `confirmedBy` operator, and lands as a HUMAN
closure: they were heard, out loud, and the claim carries the quote to prove it.
A dismissal is session state and is never written down — "that is not an answer"
is a judgement about a model's reading, not a fact about the business.

The residue is the point, not the leftovers: a statement nobody had a question
for is how the team finds the question it failed to ask.

### A demo script is read aloud in front of a client

Which makes it the one document where a wrong sentence is not a defect somebody
fixes later — it is a presenter saying "and here you'd see the dashboard" to a
room looking at a screen that has no dashboard. **Measured:** the live script
promised a Performance Trend timeline, a dashboard and a clickable Set Target.
The build had none of them. The script was written from the Experience Design's
intent, and the prototype was not one of its inputs.

Two fixes. The prototype is now UPSTREAM of the script, and `demoScriptCheck.ts`
takes the inventory FROM THE ASSEMBLED BUILD — which screens it routes to, which
controls it draws, whether it drew a widget, a measures band, a time series. A
beat promising something the build lacks is **marked, not deleted**: what the
design intended is worth knowing, and a silent drop would hide the gap between
design and build, which is exactly what a delivery team needs to see before it
stands up in front of a client.

### The people who only watch got a table of rows they will never edit

Same programme: "Executive Oversight" opened on 49 practitioners. The capability
was never missing — `metricSpecFrom` has always turned wireframe `kind: "metric"`
blocks into validated widgets. Two things kept it from mattering: nothing asked
the design for one (that Experience Design contains "metric" zero times), and a
widget could only land on a LIST screen, so the workbench — the screen an
executive actually opens — could not carry a measure at all.

Three layers, one per cause. The workbench gained a derived **measures band**
("Where this stands"), computed from the same seed the tables draw from, so a
count is a count of the rows on screen and nothing is invented. The Experience
Design brief gained *DESIGN FOR WHAT THE PERSON DOES* and *AND GIVE THEM THE
LEVER* — a number with no verb beside it is a report, not an application. And
`designCoversWatchers.ts` holds the design to it: an area whose steps are mostly
watching verbs, given no metric block anywhere, is named with its own steps as
the evidence. It reports; it never writes screens into the designer's document.

Then the gap that survived all three: every widget kind was a snapshot of NOW.
The `trend` kind buckets a date-role attribute by month, so "is this getting
better or worse" finally has an answer, and `hasTrend` became a fact about the
build rather than a standing refusal.

### The renderer's comments stopped shipping — moved, not deleted

~5.1 kB of developer reasoning was inside every prototype, read by the
stakeholder who opens it and pushed into the model's context on every
document-mode refine. The first attempt DELETED it, which was the wrong fix:
that reasoning is the only account of why the client draws what it draws.

It is restored in source, and `stripScriptComments` removes it at emit exactly
as `stripSheetComments` has always done for the sheet. Deliberately timid —
only a line that is ENTIRELY a comment goes. A trailing `// …` after code is
left alone, because a slash-slash inside a string cannot be told from a real
comment without parsing, and a wrong cut is a blank prototype rather than a
warning. It runs AFTER the `/*PERSONA-RENDERER*/` substitutions, since those
placeholders are whole-line comments to the same scanner.

**Headroom under `DOCUMENT_REFINE_BUDGET`: −190 bytes before, 5,587 after.**

## 3. Where to start

Everything the previous edition listed here has landed, except one item that
turned out to need an answer rather than work (see below). What remains:

**1 · Transcript → candidates, proven end to end.** The path is built, tested
and deployed, but it has never run on a REAL transcript — every case in
`reviewCapture.test.ts` is a hand-written fixture. The one thing fixtures cannot
tell you is what a model does with fifty minutes of people interrupting each
other. Run one review through it and read the refusals: if the refusal list is
empty on real prose, the reader is too permissive, not the model too good.

**2 · Anchored change-requests.** A "changes requested" verdict should have to
carry a screen or a fabric id. That turns a status into addressable work, and
the fabric id is what lets the request survive the next build.

**3 · Architecture Strategy is unread by the assembler — and that is correct.**
Verified again: zero occurrences in `prototypeAssembly.ts` and
`prototypeRefine.ts`. It was carried on the previous list as debt; it is not.
The assembler's entire contract is that the same inputs produce the same bytes,
and its inputs are the ones that describe WHAT THE APPLICATION IS — ontology,
atlas, blueprint, Experience Design, overrides. Architecture Strategy describes
how a real system would be BUILT: platform, integration topology, data
residency, sequencing. None of that is visible on a screen a stakeholder
validates, and feeding it in would let a hosting decision change a prototype's
layout, which is precisely the kind of coupling the fabric contract exists to
prevent. **Do not wire it.** If a future reader wants the connection, the honest
place for it is a post-condition that reads both and reports a contradiction —
never an input that lets one silently move the other.

**4 · The ontology vote.** See §5; it is the least reliable path in the product
and nobody has decided what it should do under pressure.

## 4. Traps — every one of these cost real time

**Newest first — four that cost time after the previous edition was written.**
None are caught by `typecheck`, `lint` or `check:edge-syntax`.

- **A backslash escape inside a template literal collapses.** `\d` in a renderer
  regex became `d`, so `/^\d{4}-\d{2}$/` shipped as `/^d{4}-d{2}$/` and matched
  nothing — the trend widget drew "0 months" and threw no error. **Use character
  classes (`[0-9]`) in renderer regexes, never `\d`/`\w`/`\s`.** Same family as
  the apostrophe trap (#1), and it fails far more quietly.
- **A check that stops firing looks exactly like a check that passes.** The
  measures band emitted `.m-stat`, and `demoBriefOf` keyed `hasWidgets` on that
  class — so every build looked widgeted and the dashboard check silently went
  dead. It was caught only because three tests went GREEN that should have
  stayed red. When you assert an absence, keep one case that must remain red,
  and be suspicious when anything goes green for free.
- **Deleting is not moving.** The first attempt at the shipped-comment budget
  stripped 5.1 kB of comments out of the SOURCE. The number went green and the
  only account of why the client renderer works was gone. The precedent was
  already in the file next door: keep it in source, strip it at emit. A fix that
  improves a metric by removing an explanation is the wrong fix.
- **A NUL byte, again — in the paragraph warning about NUL bytes.** See #3. That
  is three occurrences across two sessions; `noLiteralControlBytes` catches them
  in `_shared`, and caught the third.

**And the standing set:**

1. **An apostrophe inside the client renderer.** The renderer is a module-level
   TEMPLATE LITERAL, so `\'` collapses to `'` at build time and the emitted JS
   string is unterminated. The page dies with "Unexpected identifier". Use no
   apostrophes in renderer copy.
2. **A function-scoped constant used inside the renderer.** `AP_ROUTE` lives in
   `assemblePrototype`; inside `PERSONA_RENDERER` it is neither interpolated nor
   in scope, so it emitted as a bare identifier and threw at runtime — which
   took the whole approvals screen down with it. The data island already carries
   the routes (`M.apRoute` → `APR`). Read from there.
3. **Raw NUL bytes in source.** Nine of them, written as separators inside
   template literals. The BYTE is the right separator, but raw it makes the file
   BINARY to grep and ripgrep, which then skip it in silence — three searches
   returned nothing before the cause was spotted. Write it as the six characters `\u0000`, never as the byte. This
   is the second time this codebase has hit it (`prototypeRefine.ts` records the
   first).
4. **A green suite and an unchanged screen.** The design-system upgrade above.
   If a change should be visible, LOOK at it; a passing test only proves the
   thing you thought to assert.
5. **A test that pins a POSITION rather than a distinction.** Three suites broke
   on a layout wrapper because they read `screen.children` and called it "open
   sections". What makes a section open is that nothing hides it — ask that.
   Same family: a test asserting a consumer CONTAINS a string breaks the moment
   that consumer starts reaching the value through a shared builder, which is
   the better wiring. Pin the call, not the spelling.
6. **A fixture that encodes yesterday's grouping.** Three workbench cases named
   Contract and the board that first mentioned it — a fact about OWNER grouping.
   By area it moved past the four-queue cap and they went red on a build where
   nothing was wrong. The subject was "a queue", so the fixture now asks the
   document which queue it drew, and throws if none did rather than passing
   vacuously.
7. **Backtick inside a template literal** — hit again in the stylesheet. Gated
   by `check:edge-syntax`, which runs second in `validate`.
8. **Backticks in `git commit -m`** run as shell substitution. Use
   `git commit -F <file>` for any message containing code.
9. **Regenerations coalesce.** A run with `triggeredBy` other than `"user"` is
   skipped if an identical agent+program+phase ran within 5 minutes.
10. **A value supersedes an open unknown on the same locus.** Evidence must NOT
    be written as a claim beside the question it grounds, or the prior silently
    closes the question it exists to inform.
11. **Do not attribute a platform failure to your own change.** Check
    `adam_agent_runs.tokens_used` first — null on every row means no model call
    ever completed.
12. **G3 guard**: no client name in any `_shared` source, including comments.
13. If you touch `prototypeDesignSystem.ts`, regenerate the reference page:
    `npx esbuild supabase/functions/_shared/prototypeDesignSystem.ts --format=esm > .tmp-ds.mjs && node scripts/build-ds-demo.mjs` (then delete `.tmp-ds.mjs`). Never hand-edit it.
14. **Claims register**: rewording a claim line trips `claimsRegister.test.ts`.
    Re-status the row in `docs/aura/claims-register.md`, then `npm run claims:regen`.
